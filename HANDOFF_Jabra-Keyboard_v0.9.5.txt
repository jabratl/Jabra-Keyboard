3) SENIOR-ENGINEER FINDINGS (code facts; effect on phone = NOT measured)
  M1 KeyPopup.show() allocates + adds a window per key press, dismiss() removes it on release. Fix = ONE reusable PopupWindow + TextView, update text/position only (R1).
  M2 Typing commit AND feedback happen at ACTION_UP via Button click. Gboard/Ridmik give vibration/sound at DOWN. Option "feedback on touch-down" (R2). Commit stays at UP (safe: long-press hints, slide-off cancel).
  M3 feedback() uses Vibrator.vibrate(createOneShot) (binder call) and only falls back to performHapticFeedback. R2 also adds optional native tap (View.performHapticFeedback KEYBOARD_TAP) - measure by feel only.
  M4 Space swipe changes language live with no visual cue -> user cannot see where the swipe is (R3).
  M5 keyboard layout/page switch = full rebuild (R7, optional).
  OK ALREADY (do not touch): S1 KeyCfg cache, S2 AutoCapGate, backup on background thread, lazy stores, no timers/services/libraries.
  Things that can silently break (check in every step): HintKeys.attach REPLACES the touch listener set by KeyPopup.attach (one listener per letter key; popup calls go through KeyPopup.touch);
  RepeatKeyHelper (backspace) and SpaceDragHelper (space) own their touch listeners and own feedback -> never add a second listener there.
