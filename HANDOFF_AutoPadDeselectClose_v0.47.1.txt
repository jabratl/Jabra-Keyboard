FEATURE (asked: "deselect closes it automatically, manual-open case doesn't need this"):
  If the cursor pad was opened BY the v0.47.0 auto-open-on-selection feature, and the selection
  that triggered it becomes empty again (deselected), the keyboard now switches straight back to
  normal letters -- same as if you'd tapped ABC.
  A pad you opened yourself (toolbar / More settings) is NEVER auto-closed this way, exactly as
  asked -- see below for how that is kept separate.

HOW:
  - New field `autoPadOpen` (false by default). It is set true ONLY inside
    autoOpenPadForSelection() (the v0.47.0 function), and only if the pad is actually the thing on
    screen right after that call (so a failed open does not wrongly set it).
  - It is reset to false inside showLetters() itself, so ANY path back to the letters (ABC, you
    opening a different panel, closing the keyboard, etc.) always clears it -- a later MANUAL pad
    open always starts from false and can never inherit a stale "auto" flag from an earlier session.
  - onUpdateSelection(): when the new selection is empty AND autoPadOpen is true AND the pad is
    still the panel on screen, it calls showLetters(). Manual opens never set autoPadOpen, so this
    branch never fires for them.

NOT IN SCOPE (as asked):
  - Closing the keyboard fully (back button / hide) and reopening on a new field still goes through
    the pre-existing PanelKeep/onStartInputView logic, untouched here -- you only asked for the
    deselect case, not that one.
