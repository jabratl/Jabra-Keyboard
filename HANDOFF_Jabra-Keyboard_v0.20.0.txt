DECISIONS TO KEEP
 - Real password fields are ALWAYS skipped (no switch): the Privacy page promises it. The owner's "optional switch" covers email, URL, number / phone fields.
 - Jabra's own screens are never recorded (its search / dialogs / test box).
 - Paste is never saved: clip / vault / text tools / formatter reach typeText() while a panel is open and are ignored; direct commitText paste paths never call the hooks; > 64 chars in one input is ignored.
 - First ON shows a confirm dialog (HistInfo.confirmBody); after "Turn ON" hist_ack stays true. Restore / Backup never carry hist_*.
 - OFF keeps old entries until the keep time removes them or the owner taps Clear (no silent delete). Pruning also runs while OFF.
 - Data is plain text in the app-private folder (owner knows: anyone who unlocks the phone and opens Jabra can see it). Android Keystore lock / encryption = optional later, ASK FIRST.

KNOWN LIMITS / OBSERVATIONS
 - Backspace only edits the run being typed: selection delete, cut, delete-line tools and "move cursor then backspace" are not followed (the entry can keep text that is gone, or lose the wrong tail). Bangla deletes are followed per code point (Android may delete a conjunct differently).
 - Entries are runs: Enter, field / app change, 2 min idle, 500 chars end a run. Voice typing (system keyboard) is not captured.
 - Stale text found, NOT changed: PrivacyInfo.permissionLines says password fields record no clipboard history, but v0.18.12 (clip_pwd, default ON) saves copies made in password fields. Ask the owner before changing the wording or the default.
