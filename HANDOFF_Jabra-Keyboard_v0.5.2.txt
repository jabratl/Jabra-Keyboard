  --- HARD RULES FOR EVERY STEP OF THIS PLAN (speed + compatibility) ---
   P1 NOTHING new runs on the key-press path. New work happens only when a panel opens, a button is tapped, or on a background Thread. No timers, no services, no WorkManager, no new library (dependencies stay: only androidx.core-ktx).
   P2 Old keys / formats NEVER change: clips_v1 ("<0|1>,<urlencoded>" lines), fmt_cur, fmt_presets, theme (index), all existing pref keys. New data = NEW keys / NEW files only. Old behaviour = default.
   P3 Big new data (vault, backups, theme photo) = files in context.filesDir written with android.util.AtomicFile (write whole -> rename). NOT in SharedPreferences (apply() rewrites the whole XML on every save; big strings slow it). Small flags / numbers stay in prefs "jabra".
   P4 Load lazily: a store is read the first time its panel opens, never in MgbIme.onCreate / buildKeyboard. Keep the parsed list in memory only while the panel lives.
   P5 Every new UI = Kotlin panel built in code (same look as SizePanel / ThemePanel), dark + light, fits 360 px, scrolls inside capTall() height (v0.3.3). Every new logic = pure Java class + tools/*Test.java (run here).
   P6 Anything that needs a file picker (export / import / photo) lives in SettingsActivity (launcher screen). The keyboard (IME) cannot open the system picker safely. This also means NO manifest change and NO storage permission (uses ACTION_CREATE_DOCUMENT / OPEN_DOCUMENT).
   P7 Permissions: none planned. Still INTERNET only for "Check for updates", REQUEST_INSTALL_PACKAGES, VIBRATE. If a step seems to need a new one: STOP and ASK.
