1. DEBOUNCE: auto-open now waits 180 ms (AUTO_PAD_DELAY_MS). Every non-empty selection update restarts the timer;
   a deselect / showLetters() / keyboard hide cancels it. Timer re-checks the last reported selection when it fires.
2. FADE: showPanel(name, forceFade) -> auto-open gets the same 110 ms fade as a tapped panel.
   showLetters(fade) -> pad -> letters after a deselect fades in too (only that path; every other showLetters() is unchanged).
3. TRACKPAD SPEED: pref "pad_speed" (0 Slow 24dp / 1 Normal 16dp = old / 2 Fast 10dp). Settings > Tools & Panels.
   Read at every drag start, so no need to reopen the pad.
4. DOUBLE-TAP = SELECT WORD: two clean taps (no drag) on the pad's status line within 300 ms -> io.word(true,false) then
   io.word(false,true); Select switches ON so the arrows keep extending.
5. NEW FIELD RESET: onStartInputView(restarting=false): cancel timer, padPanel.reset() (Select OFF), close a pad left open,
   autoPadOpen=false. restarting=true is untouched (PanelKeep rule: a pad the user opened stays).

--- v0.48.2 ---
FIX: pad delete key "does nothing" on a selection (the keyboard's delete worked).
Cause: pad and keyboard both call MgbIme.onBackspace(); with a selection the first tap could be used up by sg.undoAutoCorrect(),
by a stale half-typed word in buf, or the app ignored the DEL key event for a (long) selection.
Now onBackspace() -> deleteSelectionNow() first: drop buf, finishComposingText + commitText("",1) in one batch edit,
and if the selection is still there, InputSafe.backspace() (DEL key) as the second try. No selection = old code unchanged.
Touches MgbIme.kt only. Applies to the keyboard's own delete key too (same function).
